## 引擎的边界从入口开始

Corduit 是网络引擎库。配置模型、规则路由、DNS 适配、用户态网络栈和协议协作在库内完成，客户端需要另外提供界面和平台生命周期。入口可以是 HTTP、SOCKS5 或 mixed 监听器；TUN 则由平台入口驱动。

一个字段能被解析，不表示对应服务存在。固定版本的校验器明确拒绝没有监听实现的 redir、tproxy 和 inbounds 中的 tun。它们必须在启动前给出可定位错误，否则用户会得到“配置已接受、请求永远没人处理”的假成功。

## 校验不止检查语法

ConfigValidator 顺序检查一般配置、DNS、入口、出口、规则和交叉引用。端口需要有效，地址需要可解析，策略引用需要能到达实际出口。控制接口的地址解析和绑定权限又是两层事：格式正确的非回环地址仍需要访问凭据。

这类检查应集中在配置边界，运行层才不必重复猜测。热重载也不能只把新对象塞进旧状态；新的引用关系、资源申请和失败回滚必须跟启动具有同样的约束。

## 同步模型如何承载并发

短任务使用工作窃取线程池，长连接使用专门连接线程和复制线程。这样一条持续传输不会无限占据本来用于 DNS、控制与定时任务的工作容量。代价是长连接有真实线程成本，所以连接预算是设计的一部分。

没有 async runtime 不意味着没有等待，也不自动意味着更快。要评价这种模型，应观察连接数、活跃程度、线程栈、握手延迟和退出成本。单个大文件与大量低速长连接给出的压力完全不同。

## 半关闭与取消是连接的一半

双向转发不能在任一方向读到 EOF 时就随意丢掉另一方向的数据。一方停止写入后，另一方可能仍有响应需要发出；正确半关闭需要把方向状态传递到对应传输。

取消则不同：它是调用方要求整个会话结束。相关 socket、复制线程和排队工作都需要看到停止信号，不能只让界面按钮变灰。统计计数也应围绕真正传过的字节更新，避免把进入缓存的数据先算成已发出。

## TUN 的数据不能提前丢弃

用户态 TCP 栈负责的不只是拆包。未确认数据需要保留以便重传，接收窗口可能变成零，序列号会回绕，FIN 也有顺序约束。固定版本的 README 记录了这些方向的修复与回归范围。

局部队列有界，意味着满载时必须定义行为：阻塞、拒绝或按网络语义丢包。上限约束的是这一层，不代表整个进程有相同的内存上限；日志应该能区分拥塞、取消与真正协议错误。

## 评估兼容性要固定 feature

协议表必须与 Cargo feature 和所用提交一起读。某个协议名称出现在文档或枚举里，不能推导当前构建已启用全部路径。需要分别核对认证、握手、传输封装和服务端版本。

一个有用的验收集应包含无效配置、认证拒绝、对端半关闭、中途取消、网络切换与并发预算耗尽。编译通过验证类型和构建路径；互操作测试验证真实对端行为，两者不能相互替代。
